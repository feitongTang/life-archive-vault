## 1. 设计目标

以单一 vault 保存日记、思考、文章与重大决策。系统用于回顾思想变化和辅助重大决策。

- **回顾思想变化。** 按月识别值得关注的变化，将不同时期的原文、经历和实际选择串成主题时间线。重点关注世界观、价值观和长期倾向。
- **辅助重大决策。** 调用与当前选择相关的历史经历，帮助用户识别遗漏的因素、权衡选项并验证关键假设。最终决定由用户作出。

## 2. Vault 结构

以 Obsidian 和 Markdown 为基础。日记、思考、文章沿用现有目录与写作方式。各模块通过笔记链接关联，按主题、日期或状态筛选时可使用 Obsidian Bases。 [Obsidian 内部链接](https://obsidian.md/help/links) · [Obsidian Bases](https://obsidian.md/help/bases)

| 模块 | 内容 | 写入规则 |
| --- | --- | --- |
| 原文 | 日记、思考、文章 | 用户写作，AI 只读。引用链接到原笔记或已有标题。 |
| 复盘 | 周、月、季度和年度复盘 | 用户复盘与 AI 月度草稿各自成篇，通过链接关联。 |
| 趋势 | 当前观察、证据时间线、适用情境、反例和纠正 | 每个主题一篇笔记。AI 提交待核对的观察和修订，用户确认后更新当前表述。 |
| 决策 | 择校、转行、伴侣关系等重大选择 | 每项决定一篇笔记。AI 提供分析，用户记录选择和事后复盘。 |

## 3. 趋势模块

趋势入口显示最新变化与待核对事项。进入主题后，先展示一句当前观察，再按日期呈现关键原句、事件背景及实际选择。每条观察都可以点回原文。 [Apple 健康趋势](https://support.apple.com/en-tm/guide/iphone/iphe3d379c32/ios)

### 证据规则

| 证据 | 处理方式 |
| --- | --- |
| 单次表述或事件 | 记录当时的想法和情境，可在相关决策中用来提出问题。 |
| 同一时期反复出现 | 形成待核对观察，注明适用范围。围绕同一件事的多篇笔记按一个事件计。 |
| 跨时间的变化或长期倾向 | 对照可比较的早期和近期材料，查找反例，并结合实际选择。变化可以逐步发生，时间线按已有证据展开。 |
| 用户确认或纠正 | 保存用户的原话、日期和适用范围。后续分析先读取这些记录。AI 对既有结论的修订另列为候选。 |

量化信息用于说明**证据覆盖**，包括独立事件数、涉及的时间段和缺少记录的月份。主题在日记里出现的次数仅反映记录频率。行为指标可按次比较，例如重大决策前实际验证过的假设。主观体验可选用同一问题重复自评，缺失的数据点留空。 [个人自我追踪研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC12435389/)

## 4. 复盘与月度整理

| 周期 | 复盘产出 |
| --- | --- |
| 周 | 记录值得回看的经历、仍待解决的问题和需要跟进的决定。 |
| 月 | AI 根据新增材料生成月度草稿，列出值得核对的变化、反例或旧观察的修订。 |
| 季度 | 对照各月观察及其原文，辨别持续出现的变化和特定情境下的反应。 |
| 年 | 回顾重点主题的时间线，梳理世界观、价值观的变化及其对实际选择的影响。 |

### 月度任务

1. **调度。** 初始设定为每月 1 日运行，使用 Asia/Shanghai 时区，整理上一自然月。
2. **读取。** 按写作日期选取目标月的资料，同时读取既有观察与用户纠正。需要核对变化时，检索相关旧文、反例和决策记录。迟录或修订的旧笔记作为补充材料，标注原月份。回忆性材料标明事件日期与记录日期。
3. **生成。** 每月最多三条。每条以一句具体观察开头，附日期、情境、短原句和链接。存在反例或证据缺口时一并写明。逐条核验引文支持相应判断。句子只保留具体信息，省去泛泛的性格概括。没有足够依据时记为「本月暂无」。
4. **写入。** 每月使用一个固定的草稿文件。新主题标为「待核对」，已有主题追加依据或候选修订。重跑更新对应月份的 AI 草稿，按主题和事件去重，保留用户批注及已确认的表述。资料读取失败时记录缺口并支持补跑。引用来源失效时标记相关观察为「需重查」。
5. **权限。** 日记、文章及决策等资料均可按需交由云端 AI 分析。每次任务读取所需资料，写回范围限于 AI 草稿及趋势笔记中的 AI 内容。

## 5. 重大决策模块

| 记录阶段 | 内容 |
| --- | --- |
| 决策背景 | 要决定的事项、当前选项、时间约束、已知条件和最看重的因素。 |
| 分析与验证 | 并排比较选项的收益、代价和未知项。说明判断来自当前事实、个人经历还是推测。引用相关原文，指出当时与当前情境的差异，提出一至两个可验证且足以影响决定的问题。 |
| 最终选择 | 用户记录自己的选择、主要理由、愿意接受的代价，以及触发重新考虑的条件。 |
| 事后复盘 | 保留结果、当初假设的验证情况和下次可复用的经验。决策时已知信息与后来发生的结果分别留存。 |

**典型场景**　转行时分别评估离开当前行业的理由与新岗位本身的适配度。若后者信息不足，优先核实足以改变决定的因素，例如团队的实际工作方式或岗位能否提供预期的成长机会。待核对的长期观察可以用来提醒用户检查某个问题。

## 6. 实施与验收

| 阶段 | 验收条件 |
| --- | --- |
| 资料试跑 | 用一个已结束的月份试跑，按需纳入少量历史资料。月度草稿的引文可核对，五分钟内可读完。 |
| 趋势检验 | 同一事件的多篇记录能够去重。单次表述保留情境，长期观察有跨时间依据。补充用户纠正后，重跑仍沿用该纠正。 |
| 决策检验 | 用一次已有跳槽经历试走流程。输出能分别分析离职理由和新岗位适配度，并给出至少一个可实际验证的问题。 |
| 自动化接入 | 验证运行环境能在预定时间读取 vault，且只写入指定范围。重复运行、资料缺失和补跑均有明确结果。 |

模型、调度工具与图表实现方式在试跑后选定。首版以月度草稿、主题时间线和决策笔记验收。
