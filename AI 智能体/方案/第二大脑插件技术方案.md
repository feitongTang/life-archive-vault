## 1. 目标与范围

在桌面端 Obsidian 打开「人生存档」，可以写当天的日记、打开任意周期复盘、记录思想文章，也可以从近期摘要追溯原文。Vault 以 Markdown 保存原始资料、复盘及决策记录。插件关闭后，这些笔记仍可通过 Obsidian 的文件、搜索和链接使用。

| 阶段 | 交付范围 |
| --- | --- |
| 首版 | 桌面首页、日记、周／月／季／年复盘、思想文章。首页展示记录日历、近期文章、最近复盘摘要和最多三个有来源的关键词。按月产出 AI 复盘草稿，支持手动试跑、补跑和 Codex 定时运行。 |
| 后续趋势模块 | 按主题串联原文、事件、实际选择及反例。手动触发 AI 候选观察，经用户确认后更新趋势笔记。 |
| 后续项目与决策模块 | 支持主线、支线、里程碑复盘、重大决策跟进和正式档案。人生地图用 Canvas 连接已有笔记。RPG 属性评分作为后续可选能力，待证据与评分口径验证。 |

本文将当前讨论收敛为技术设计。首页首版以摘要和关键词为准。长期主线以里程碑为单位复盘。背景见 [[AI 第二大脑方案]]、[[人生存档主页设计方案]]、[[重大决策模块设计方案]]。

## 2. 技术选型与复用

采用 **桌面 Obsidian 插件 + Markdown Vault + Codex 复盘工作流**。插件用 TypeScript、Obsidian API 和原生 DOM/CSS，构建沿用官方示例的 esbuild 配置。用 `ItemView` 提供「人生存档」，通过命令和入口按钮打开。Obsidian 负责 Markdown 编辑、文件导航、内部链接与主题适配。复盘工作流独立于插件进程，定时和手动运行使用相同的选材、权限和写入逻辑。 [官方插件模板](https://github.com/obsidianmd/obsidian-sample-plugin) · [Obsidian 插件生命周期](https://docs.obsidian.md/plugins/guides/lifecycle-management)

| 路线 | 取舍 |
| --- | --- |
| 插件与 Codex 分工（建议采用） | 日常记录可离线使用。Codex 提供 AI 执行和调度，插件通过读取同一份复盘笔记显示结果。需要定义统一的文件和权限协议。 |
| 由插件直接调用模型并调度 | AI 入口集中，但插件需要处理模型配置和定时补偿。若需在 Obsidian 关闭后运行，还要有独立执行环境。 |
| 安装完整的 Daniel Miessler LifeOS | 已有记忆、工作流与运行监控，但其目录、配置及运行环境会同时进入项目。当前可借鉴 Cortex 的来源追溯、Vigil 的运行记录、TELOS 的目标与现状对照。 |

周期计算、模板应用、查找或创建笔记优先查阅 `quanru/obsidian-lifeos` 的对应源码。开发前固定参考版本，核对日期边界、独立性及许可证。若函数能独立复用，保留出处和许可声明。首版运行时由本插件负责周期操作。 [Obsidian LifeOS 源码及许可](https://github.com/quanru/obsidian-lifeos) · [Daniel Miessler LifeOS 的 Cortex](https://github.com/danielmiessler/LifeOS/blob/main/LifeOS/install/skills/Cortex/SKILL.md) · [LifeOS 工作流](https://github.com/danielmiessler/LifeOS/blob/main/Releases/v8.761.0/README.md#work-that-runs-without-you-workflows-vigil-and-statvs)

## 3. Vault 文件约定

以下是默认路径。插件和复盘工作流读取同一份本地配置中的目录映射、模板与时区。首次初始化补齐缺失目录和模板，遇到已有文件时复用或报告冲突。

| 内容 | 路径示例 |
| --- | --- |
| 周期笔记 | `周期笔记/日/2026-11-18.md`、`周期笔记/周/2026-W47.md`、`周期笔记/月/2026-11.md`、`周期笔记/季/2026-Q4.md`、`周期笔记/年/2026.md` |
| 思想文章 | `思想/关于学习的几个问题.md` |
| AI 月度复盘 | `复盘/AI/2026-11.md` |
| 模板 | `模板/日笔记.md`、`模板/周笔记.md` 等 |
| 后续模块 | `项目/`、`趋势/`、`决策/`，启用相应模块时创建 |

日、周、月、季、年分别存放在「周期笔记」下的对应子目录。文件名也是 Obsidian 显示的笔记标题，默认模板从正文栏目开始。日、月、季、年按 `Asia/Shanghai` 自然日历计算，周按 ISO 周年和周号计算。用户复盘模板与 AI 复盘使用可预先计算的相对目标路径互链。目标尚未创建时，首页标为待生成或待创建。AI 定时任务写入自己的产出，通过固定路径与既有用户笔记建立关联。

YAML 只保留机器需要的属性。首版通用属性 `ai` 用于权限。思想文章若要按写作日期纳入当月复盘，可用选填的 `date`，缺日期时可通过显式选材纳入。周期从路径取得。AI 复盘的摘要、关键词、覆盖情况与引文放在有固定标题的 Markdown 正文中。首页按约定读取相应章节，从同一份内容渲染，无需另存一份摘要。后续需要跨项目追踪的里程碑、趋势和决策再引入稳定 ID。

## 4. 模块边界

| 模块 | 职责 |
| --- | --- |
| Vault 访问 | 目录配置、笔记分类、模板、文件打开／创建与内部链接。插件内优先使用 `Vault`、`MetadataCache` 和 `FileManager`。 |
| 周期笔记 | 把日期与周期类型映射到路径和模板。已存在就打开。并发创建遇到同一路径已存在时重新打开。 |
| 首页 | 汇总日历状态、近期文章和最近完成的 AI 复盘。监听相关文件变化后刷新受影响的区域。点击关键词可先到复盘观察，再打开来源。首页跟随 Obsidian 明暗主题，使用简洁排版、清晰焦点与键盘导航。 |
| AI 复盘工作流 | 在插件进程外选材、调用 Codex、验证输出、提交产物和记录运行状态。可独立对指定月份试跑。 |
| 共享规则 | 维护路径规范、权限计算、AI 复盘格式和写入约束。构建时供插件使用，运行时供本地复盘工具使用。 |

首版按配置目录和日期索引 Markdown。首页启动只需读取可见区间和最近复盘，文件变化时增量刷新。Obsidian 内更新已有笔记时按当前文件内容合并，采用 `Vault.process` 等平台 API。 [Obsidian Vault API](https://docs.obsidian.md/Plugins/Vault)

## 5. AI 权限与写入

| `ai` | 行为 |
| --- | --- |
| `off` | AI 读取和写入均关闭。 |
| `read` | 可在获准任务中读取、摘要、引用。 |
| `write` | 可读取，并允许获准的工作流提交该笔记或其授权区段的更新。 |

实际权限取目录上限、笔记声明和本次任务能力的交集。周期笔记和思想文章的目录上限为 `read`，写入 `ai: write` 也无法提高上限。纳入 AI 读取范围的目录内，缺字段按 `read` 处理，无法识别的值按 `off` 处理。其他目录按配置显式纳入。用户从首页新建或编辑笔记属于用户操作。

月度定时任务只可提交目标月份的 AI 复盘和本次运行记录。新复盘由模板赋予 `ai: write`。重跑从最新文件内容合并，更新标记明确的 AI 区域，保留用户批注及确认记录。原文件在生成期间变化时，提交阶段再次检查版本和权限。遇到权限变化、标记损坏或合并冲突时保留候选结果并报告原因。同月运行互斥，成功产出使用同目录临时文件和原子替换提交。后续手动 AI 操作通过预览或确认后调用同一套写入检查。

`ai` 是应用层权限。定时复盘应把筛选后的输入交给模型，由受控工具校验并提交结果。验收需要确认实际执行环境能否把模型直接可见、可写的路径限制在工作流范围内。若无法隔离，则将其记录为应用层约束，先用副本试跑。日志记录月份、状态、文件路径与失败原因，避免复制日记正文。

## 6. 首版月度工作流

1. **定位周期。** 定时任务在每月 1 日按上海时区处理上一自然月，手动运行明确指定目标月。周、季、年首版提供用户复盘入口，AI 自动化从月度开始。
2. **准备资料。** 使用写作日期选择当月日记、文章与用户复盘，按需回查相关旧文和已确认的订正。迟录或回忆性材料分别标记写作日期与事件日期。读取失败与资料缺失要单独记录。
3. **生成并验证。** 输出简短摘要和最多三个具体观察。每条包含关键词、情境、原文短引与链接。按事件去重，核对引文存在、链接可解析。证据不足时可以少写或留空，并说明覆盖情况。
4. **提交与展示。** 在通过权限和冲突检查后更新同月草稿，记录成功、资料不足或失败。首页保留最近一次可读的复盘，并显示对应月份。目标月失败时可补跑该月。

Codex 调度接入前，用本地样本验证读 Vault 和写入产物的路径。分别测试 Obsidian 已关闭、设备休眠后恢复以及权限不足的表现，据此确定补跑方式和运行预期。

## 7. 后续模块如何接入

- **趋势。** 复用复盘引文与笔记链接，在用户手动启动后提取候选。每个主题积累跨期依据、反例和人工订正。确认后才更新当前观察。引用丢失时标记需重查。
- **项目与里程碑。** 项目入口说明目标、相关主线或支线及里程碑。阶段复盘记录预期、结果、差异、下一步和重大决定。长期主线的决定在相应阶段进入跟进。阶段复盘或结束复盘中核对的决定，由用户明确确认后归档。
- **决策与人生地图。** 正式决策保存当时的选项、约束、选择与假设，再追加结果和事后归因。同一决策在不同阶段出现时，引用同一档案并补充来源。Canvas 节点链接项目、里程碑和决策笔记。首页按需增加入口。

## 8. 实施顺序与验收

| 顺序 | 验收 |
| --- | --- |
| 1. 文件与周期 | 在测试 Vault 验证五种周期按模板打开或创建。重复点击、跨年 ISO 周、季度边界和重复初始化均正确。文章可创建、打开、回看。 |
| 2. 桌面首页 | 从「人生存档」完成日记、复盘、文章的日常操作。明暗主题、窄分栏和键盘可用。无复盘时日历和记录入口仍可工作。 |
| 3. AI 复盘试跑 | 选一个已结束的真实月份和少量历史材料。逐条核验原文，测试同月补跑、权限上限、手工批注、断链和冲突。摘要和关键词能从首页追溯。 |
| 4. 定时运行 | 验证目标时区、输入路径、输出权限、失败记录和补跑。实际读写边界和调度条件通过验证后再启用。 |

评审时主要确认两项。第一，首版自动化从**月度**开始，周、季、年先保留手写入口。第二，首页可展示带「AI 草稿」标识的最新月份摘要与关键词，用户确认仍用于长期趋势和正式决策。当前 Vault 尚无真实日记、文章或任务材料可供试跑，开发验收需要一个代表性月份。周期代码可移植性、定时任务的文件访问与补跑表现属于开发前验证项。
